# 训练模拟器优化方案

状态：已确认。第一段和第二段已按本文实现。第三段（上下文并行、专家并行、自动搜索）尚未实现。

本文档是第一版之上的优化设计。第一版已经能讲清一步训练的显存、通信和播放。这次补的是一步外面的作业：语料怎么分、整次要跑多久、配方和检查点里有什么、多机卡住时长什么样、以及并行度该怎么摆。

模拟器仍然不启动真实训练，不占用 GPU，不读磁盘上的数据集，也不做与 NCCL 对齐的时钟级仿真。

## 1. 这次采纳的设计

同类项目分成三类，这次只借它们的分法。

| 来源 | 采纳 | 不采纳 |
| --- | --- | --- |
| llm-analysis、Calculon | 一步仍是纯函数。整次作业的步数、墙钟时间和 GPU 时由这一步乘出来 | 不把几十万步逐条播放 |
| gpu-mem-calculator | 页面继续先给显存和能否放下 | 不把产品收成只剩一张显存表 |
| nanoGPT、CS336 | 学习率日程、梯度裁剪、检查点内容、数据读到哪，放在作业配置里 | 不把这些项写进显存和通信公式 |
| llm-analysis、Megatron Core | 上下文并行、专家并行以后作为和张量并行并列的整数 | 本方案前两段不改并行公式 |
| Galvatron、Calculon | 并行度先给一条建议 | 不做自动搜索 |
| SimAI、ASTRA-sim | 通信继续用现在的带宽公式 | 不引入包级网络 |

播放日志是这些计算器没有的一层，保留。播放步数仍然是演示长度，上限 300。语料有多少 token、整次作业有多少步，写在计划里一次算完。

## 2. 不改什么

下面这些保持第一版的数值，旧的六个预设和现有测试继续有效。

- 显存账单、取数时间、计算时间、通信时间、优化器时间、暴露通信、流水线气泡、模型 FLOPs 利用率、加速比。
- 损失曲线的形状、噪声和多机上的那一次跳动。
- 学习率默认仍是「先升温，再保持配置值」。余弦衰减是新选项，默认关闭。
- 检查点默认仍是步数不少于 8 时，播放中途打一行日志，不把磁盘时间加进预览的步时。
- 语言不进入损失种子。播放速度只改变推送间隔。
- 计划函数仍是纯函数：相同配置得到相同计划。随机损失和慢卡只出现在播放里。

新字段都有默认值。旧的请求体不带这些字段时，计划里多出来的作业摘要用默认值算出，一步的时间和显存与现在相同。

## 3. 配置

`TrainConfig` 增加以下字段。

| 字段 | 默认 | 作用 |
| --- | --- | --- |
| `dataset` | `none` | 教学语料。`none` 表示不外推整次作业 |
| `pack_sequences` | `true` | 序列是否拼接。只影响讲解里的有效 token，不改步时 |
| `lr_schedule` | `warmup_constant` | `warmup_constant` 或 `warmup_cosine` |
| `weight_decay` | `0.1` | 写进配方讲解和启动日志 |
| `grad_clip` | `1.0` | 同上 |
| `ckpt_every_steps` | `0` | `0` 沿用第一版的中途一行日志。大于 0 时按播放步间隔保存，并估算磁盘时间 |
| `resume_step` | `0` | 大于 0 时，启动日志先说明四样状态已恢复 |
| `eval_every_steps` | `0` | `0` 表示只在播放最后一步做一次验证。大于 0 时按间隔估算验证时间 |
| `fault` | `none` | `none` 或 `nccl_timeout` |

取值范围：`weight_decay` 为 0 到 1，`grad_clip` 为 0 到 100，`ckpt_every_steps`、`eval_every_steps`、`resume_step` 为 0 到 1_000_000。`resume_step` 不要求小于播放步数，因为播放只是整次作业开头的一段。超出范围时接口返回 422，与现有数值范围相同。

目录增加教学语料，只记录 token 总数：

| id | 名称 | token 数 |
| --- | --- | --- |
| `none` | 不外推整次作业 | 无 |
| `tok_10b` | 100 亿 token | 1e10 |
| `tok_100b` | 1000 亿 token | 1e11 |
| `tok_1t` | 1 万亿 token | 1e12 |

名称有中英两份。这些数字用来换算步数，不对应某份公开语料的精确规模。

## 4. 计划里的作业摘要

`build_plan` 在现有字段之外增加 `job`。预览和播放共用这一份。

每步全局 token 已经在 `batch.global_tokens` 里，等于 `micro_batch * grad_accum * seq_len * dp`。作业摘要直接引用它，不另写一套。

```text
tokens_per_step        = batch.global_tokens
tokens_per_rank_step   = micro_batch * grad_accum * seq_len
full_steps             = ceil(corpus_tokens / tokens_per_step)    仅当选择了语料
playback_wall_s        = steps * step_s
full_wall_s            = full_steps * step_s                      仅当选择了语料
gpu_hours              = world * full_wall_s / 3600               仅当选择了语料
effective_token_ratio  = 1.0（拼接）或 0.7（不拼接）
```

`step_s` 用预览里的步时，不含慢卡，不含磁盘。有效 token 比例只出现在讲解里：不拼接时说明大约三成位置被补齐吃掉。模型 FLOPs 利用率和吞吐仍按 `tokens_per_step` 计算，避免和第一版的数字分叉。

数据怎么分到 rank：数据并行秩 `r` 读取满足 `sample_index % dp == r` 的样本。播放结束时，该 rank 的读取位置是 `(resume_step + 已播放步数) * tokens_per_rank_step`。计划里写出这个式子和当前配置下的数字。

模型 FLOPs 利用率沿用现有算法。稠密模型再标一个教学区间：低于 0.25 时讲解指向数据或通信，0.25 到 0.55 视为常见区间，高于 0.55 时说明教学效率系数可能偏乐观。这不阻止启动。

验证时间不进训练步时。`eval_every_steps` 大于 0 时，每次验证按训练步时的 0.15 倍再乘 4 个验证批次估算，在 `job.eval_s` 里单列。默认仍只在播放最后一步打一行验证日志，不增加这段时间。

## 5. 配方

默认日程与第一版相同：升温步数为 `max(1, min(10, steps // 5))`，之后学习率保持配置值。`steps` 为 1 时不升温。

选择 `warmup_cosine` 时，日程按 token 走。视野用整次作业的 token；没有选择语料时，视野退回这次播放的 token。前 1% 的 token 线性升温到配置学习率，之后按余弦降到峰值的 10%。播放中的某一步，用 `(resume_step + step) * tokens_per_step` 去查这个日程。损失曲线仍用第一版的教学曲线，不随学习率改形。

梯度裁剪和权重衰减出现在启动日志和一张配方讲解里。它们不改变损失、显存和步时。

精度继续用现有选项，显存字节数不变。讲解分开写：BF16 不使用损失缩放；FP16 从损失缩放 65536 开始。仅当精度为 FP16 且播放步数不少于 4 时，在第 `max(2, steps // 3)` 步打一行梯度溢出，损失缩放减半，该步不更新权重。现有预设都是 BF16，这条路径不会进入旧测试。

损失图的标题下补一句：词表约 32000 时，真实交叉熵的起点约在 10 nat 附近；图上的曲线是教学形状，不是这份语料的成绩。曲线本身的 4.6 到 1.85 不改。

## 6. 检查点

计划里的 `job.checkpoint` 写明每个 rank 要保存的四样东西：参数、优化器状态、随机数、数据读到哪。随机数的体积忽略。字节数用本卡显存账单里的参数和优化器，不含梯度、激活和开销：

```text
ckpt_bytes = param_bytes + optim_bytes
ckpt_s     = ckpt_bytes / (2 * 10^9)
```

2 GB/s 是教学用的本地盘带宽，不是某款磁盘的标称值。优化器若在 CPU 上，字节数仍按那份状态计算，讲解里说明它从 CPU 内存写出。

`ckpt_every_steps` 为 0 时，行为与第一版相同：播放步数不少于 8 时中途一行日志，预览步时不含磁盘。大于 0 时，播放步号能被该间隔整除就进入检查点阶段，该步的播放步时加上 `ckpt_s`，日志写出字节数和耗时。预览里的 `timing.step_ms` 仍然不含磁盘，磁盘时间放在 `job.checkpoint.ckpt_ms`，页面在步时旁边单独标出。这样第一版对「暴露通信长于计算」的断言保持不变。

`resume_step` 大于 0 时，启动日志在进入训练循环之前写明：参数、优化器状态、随机数和数据位置已从第 `resume_step` 步恢复。不模拟文件损坏和版本不匹配。

## 7. 并行度建议

计划增加 `advice`，每条有 `level`（`info` 或 `warn`）和中英文本。建议不改写使用者的 `tp`、`pp`，也不禁止启动。警告同时放进现有的 `warnings`，沿用页面上的警告条。

规则按这个顺序：

1. Megatron 且张量并行度大于每节点 GPU 数：警告层内通信跨出节点。这条与第一版已有的跨节点讲解并存。
2. Megatron 且张量并行度不能整除每节点 GPU 数：警告一个张量并行组被拆到两台机器上。
3. 流水线气泡比例大于 0.30：警告气泡吃掉了计算。
4. 当前框架放不下，而同模型在分片框架下有机会放下：建议改用 FSDP 或 ZeRO-3。只给方向，不替使用者改框架。
5. 其余情况给出一条信息：张量并行优先占满节点内的卡，余下的卡给数据并行，流水线只在层数划得开、气泡可接受时再加。

上下文并行和专家并行不在本段实现。第三节末尾规定它们以后怎么加。

## 8. 播放

启动日志在第一版的七步之内追加，不删现有句子。测试仍要能看到 `[模拟]`、`torchrun` 或对应框架的启动命令、`进入训练循环`、显存不足时的 `分配失败`。

追加的内容：

- 选择了语料时，写明整次作业的 token、步数、墙钟时间和 GPU 时，并写明这次播放只覆盖前 `steps` 步。
- 写明每个数据并行 rank 的分片方式和拼接与否。
- 写明梯度裁剪、权重衰减和学习率日程的名称。
- `resume_step` 大于 0 时写恢复的四样状态。

`fault` 为 `nccl_timeout` 时，在第 `max(2, steps // 3)` 步停止。状态为新的 `timeout`。日志包含：停住的 rank（固定用该步所在数据并行组里 local rank 最大的那个）、步号、集合操作名称（沿用这一步本来要做的通信）。不再把慢卡的 25% 加时叠在同一步上。预览仍然可以启动。显存不足优先于这个故障：放不下的配置仍在分配失败处结束。

状态增加「通信超时」。中英分别为「通信超时」和「Timed out」。其余状态不变。

## 9. 页面

仍是一页。左栏在「模型与批次」和「播放」之间增加三组，框架切换时不隐藏它们，因为数据和配方与框架无关：

- 数据：语料、序列拼接。
- 配方：学习率日程、梯度裁剪、权重衰减。学习率输入留在原处。
- 作业：检查点间隔、续训起始步、验证间隔、故障。故障默认「无」。

右栏在现有指标下增加作业摘要：每步 token、整次步数、墙钟时间、GPU 时。未选语料时，整次步数和 GPU 时显示为「未外推」，播放时长仍用 `steps * step_ms`。检查点磁盘时间单独一行，不画进现在的步时条。建议写在现有讲解卡片的最前面。

中部集群、分隔条和日志区的格局不变。

新文案走现有的中英切换。目录接口增加 `datasets`。`job`、`advice` 随预览和播放里的计划一起返回。

## 10. 预设与验收

第一版六个预设不改配置，只是响应里多了默认的 `job` 和 `advice`。另外增加三个预设：

| id | 要看到的事 |
| --- | --- |
| `token_budget` | 4×A100、FSDP、7B、1000 亿 token。播放仍是十几步。摘要给出整次步数、墙钟时间和 GPU 时 |
| `resume_job` | 同上，`resume_step` 大于 0，`ckpt_every_steps` 大于 0。启动日志先恢复，保存那一步带磁盘时间 |
| `hang_rank` | 两节点、DDP、10GbE。播放在集合通信超时处停止，日志有 rank、步号和操作名 |

验收：

- 旧测试全部通过。六个旧预设的 `timing` 和 `memory` 与现在一致。
- `token_budget` 的 `full_steps` 等于 `ceil(1e11 / global_tokens)`，`gpu_hours` 等于 `world * full_steps * step_s / 3600`。
- 打开或关闭序列拼接，`timing` 不变，讲解里的有效 token 比例分别是 1.0 和 0.7。
- `warmup_cosine` 不改变 `memory` 和 `timing`。
- `ckpt_every_steps` 大于 0 时，`timing.step_ms` 不变，`job.checkpoint.ckpt_ms` 大于 0。
- 张量并行跨出节点时，`advice` 里有一条 `warn`。
- FP16 播放含一次缩放减半；BF16 播放没有。
- `hang_rank` 的事件流以 `timeout` 结束，且在该事件之前没有 `done`。
- 中英两套文案都能生成；默认仍是中文。

## 11. 分段实现

**第一段。** 第 3 到第 7 节、第 9 节，以及 `token_budget`、`resume_job`。这是本方案确认后要写的代码。

**第二段。** 第 8 节的故障播放和 `hang_rank`。它增加一种结束状态，单独做，避免和作业摘要缠在一起。

**第三段。** 上下文并行和专家并行。上下文并行是 Megatron 上的整数 `cp`，要求能整除序列维度的教学约数；激活和张量并行通信按 `cp` 再除。专家并行先在模型目录里加一个混合专家约数，通信用 AllToAll，进程数变为 `tp * pp * cp * ep * dp`。这两项各自带预设和测试，不提前改第一段的公式。

再往后才考虑的内容：自动搜索并行度、把两份配置并排对比、包级网络。它们都不在本方案的实现范围内。
